# Interview Shala LiveKit worker

This process runs the real-time interviewer and persists transcript turns through the API's private worker endpoints.

## Requirements

- Python 3.12+
- LiveKit Cloud project credentials
- Deepgram API key
- Cartesia API key
- OpenRouter API key
- Interview Shala API reachable from the worker
- A shared random secret configured in both the API and worker environments

## Local development (Windows PowerShell)

```powershell
cd apps/worker
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
Copy-Item .env.example .env
# Fill the provider credentials and shared secret in .env
python -m src.agent dev
```

The worker expects room names in the format `interview-shala-{practice-session-uuid}`, matching the room names generated by the API token endpoint. LiveKit dispatches the default agent when a participant joins a room.

## Runtime configuration

The worker uses Deepgram Nova-3 for English-India speech recognition, OpenRouter through the OpenAI-compatible Chat Completions interface for the interviewer model, and Cartesia Sonic 3 for speech synthesis. Silero VAD runs in the worker process.

The API's `WORKER_SHARED_SECRET` must match the worker's value. Never expose this secret to the browser or commit either environment file.

## Transcript trust boundary

Only final STT transcripts and committed assistant messages are sent to the private API. A single ordered writer serializes turns and drains its queue before a normal worker shutdown completes. Failed writes are surfaced in worker logs and stop later sequence writes rather than silently creating sequence gaps. The API authenticates the worker using the shared secret, treats exact retries as idempotent, and rejects conflicting content at an existing sequence number. Browser transcript endpoints remain separately labelled `client` and are not trusted evaluation evidence.

This worker does not calculate scores or update skill profiles. Evidence extraction and rubric-based evaluation are later milestones.

## Deployment

Build from the repository root using `apps/worker/Dockerfile` as the Dockerfile path and set the worker environment variables in the deployment secret manager. Run one worker service for the LiveKit project. Do not deploy the worker until the API has the matching shared secret and is reachable from the worker network.
